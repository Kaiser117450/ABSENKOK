  <action>
    Extend the packaging entrypoint so every signed release version retains the matching symbol outputs.

    Required behavior:
    1. Add a `symbols/` directory under the staged release directory and pass `--split-debug-info=<symbolsDir>` on release `appbundle` and `apk` builds.
    2. Keep `--obfuscate` off by default; v7.0 only requires retained symbols, not a new obfuscation rollout.
    3. Copy `build/app/outputs/mapping/release/mapping.txt` into the staged release directory when it exists.
    4. Record symbol and mapping paths in `release-manifest.json`.

    Scope guard:
    - do not enable obfuscation unless the plan explicitly adds a second, justified decision
    - do not store symbol outputs outside the versioned release directory
  </action>
  <verify>
    <automated>powershell -Command "Select-String -Path 'tool/release_build.ps1' -Pattern 'split-debug-info','mapping.txt','symbols'"</automated>
  </verify>
  <done>The staged release directory now retains the symbol material needed to debug shrunken signed releases later.</done>
</task>

  <action>
    Add a smoke-verification path that proves the shrunken signed release starts on Android before distribution.

    Required behavior:
    1. Support a `-SmokeVerify` mode on `tool/release_build.ps1`.
    2. In `-CheckOnly -SmokeVerify` mode, validate that the script knows how it will find `adb`, the signed APK path, and the evidence file path without requiring an attached device.
    3. In real `-SmokeVerify` mode, require at least one attached device or emulator, install the signed release APK, launch the app package, and capture timestamp, device serial, version, and command results into `smoke-check.txt`.
    4. If the APK was only built for smoke installation and should not be distributed, mark that decision explicitly in `release-manifest.json`.
    5. Update `docs/android-release-contract.md` so the tracked contract states that symbol retention and smoke evidence are both required before distribution.

    Scope guard:
    - do not silently skip smoke verification when no Android target is attached
    - do not widen this into a full human runbook or cloud release pipeline
    - do not let smoke-only APK generation quietly become the default distributed artifact
  </action>

  </verify>
