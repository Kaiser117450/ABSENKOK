  <action>
    Create `tool/release_build.ps1` as the only packaging entrypoint for Phase 48.

    Required behavior:
    1. Support `-CheckOnly` so the repo can validate the lane structure and expected inputs without building signed artifacts.
    2. In real build mode, enter through `tool/release_env.ps1` and then call `tool/release_preflight.ps1`; if preflight fails, stop immediately.
    3. Resolve `versionName` and `versionCode` from tracked project metadata and use them to derive a staged release directory name.
    4. Build a signed `.aab` as the canonical release artifact every time.
    5. Support an explicit `-IncludeSideLoadApk` switch that builds and retains a signed release `.apk` only when the operator asks for that path.
    6. Copy the retained artifact set into a versioned release directory under `build/releases/android/`.
    7. Write `release-manifest.json` (or equivalent machine-readable manifest) that records the version, timestamp, git revision when available, and whether the APK was retained, omitted, or only built for smoke use later.

    Scope guard:
    - do not let a real build skip preflight
    - do not retain the APK by default just because the build can make one
    - do not add symbol retention or smoke verification in this task yet
  </action>
  <verify>
    <automated>powershell -ExecutionPolicy Bypass -File tool/release_build.ps1 -CheckOnly</automated>
  </verify>
  <done>The repo has one packaging entrypoint that validates itself, respects preflight, and stages the agreed artifact set into a deterministic release directory.</done>
</task>
