# Phase 56 - UI Design Contract

> Visual and interaction contract for Phase 56: Server-Time Scan Authority.
> Generated by gsd-ui-researcher from Phase 56 context/research and the current Flutter kiosk surfaces.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none (Flutter / Material 3) |
| Preset | not applicable |
| Component library | Material 3 (Flutter built-in) |
| Icon library | Material Icons (Flutter built-in) |
| Font | Plus Jakarta Sans (`google_fonts`) |

Source of truth:
- `lib/core/theme.dart` for palette, typography baseline, radius, and button rhythm
- `lib/screens/kiosk/kiosk_idle_screen.dart` for idle-shell hierarchy, pending badge/banner, and kiosk motion language
- `lib/screens/kiosk/kiosk_scan_screen.dart` for action selection, success/error states, and current auto-close behavior
- `.planning/phases/55-schedule-policy-absence-rules/55-UI-SPEC.md` for adjacent milestone consistency

Phase 56 stays inside the existing Flutter kiosk design system. No new design library, routing pattern, or visual language reset is allowed.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Inline icon gaps, badge separators, helper-copy spacing |
| sm | 8px | Tight vertical rhythm between labels, stacked helper rows, button groups |
| md | 16px | Default card padding, dialog body padding, horizontal screen padding |
| lg | 24px | Section spacing inside scan and success screens |
| xl | 32px | Major vertical separation between employee card, action block, and footer |
| 2xl | 48px | Minimum safe touch-target rhythm and large modal/button spacing |
| 3xl | 64px | Primary scan action height and large focal spacing on kiosk screens |

Exceptions:
- The existing pending sync strip stays 36px tall for continuity with the idle header contract.
- The success medallion may remain a 100px circle because the kiosk is viewed at distance.
- All tappable controls must keep a minimum 48x48px touch target even when visual padding is tighter.

## Typography

Use only 4 core sizes and 2 weights in new Phase 56 surfaces.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14sp | w400 | 1.5 |
| Label | 12sp | w700 | 1.25 |
| Heading | 18sp | w700 | 1.2 |
| Display | 28sp | w700 | 1.1 |

Phase 56 hierarchy:

| Element | Size | Weight | Color |
|---------|------|--------|-------|
| Break-first dialog title | 18sp | w700 | `AppColors.textPrimary` |
| Action button label (`MASUK`, `ISTIRAHAT DULU`) | 14sp | w700 | semantic action color |
| Success heading (`Berhasil!`, `Tersimpan Sementara`) | 28sp | w700 | `AppColors.textPrimary` |
| Authoritative time value (`07:02 WITA`) | 28sp | w700 | `AppColors.textPrimary` |
| Status line (`Masuk tercatat`, `Istirahat dulu disimpan`) | 18sp | w700 | semantic state color |
| Employee name and helper copy | 14sp | w400 | `AppColors.textSecondary` |
| Pending/footer/helper copy | 12sp | w400 | `AppColors.textMuted` or queued-state text color |

Typography rules:
- Do not introduce a third weight for this phase. Existing legacy `w800/w900` code can be normalized down as Phase 56 touches those surfaces.
- The idle-screen clock may stay visually large, but it must never be labeled or implied as the authoritative scan time.
- Only live-confirmed scan feedback may use the `WITA` label.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#FFFFFF` | Kiosk background, scan scaffold, confirmation surfaces |
| Secondary (30%) | `#F9FAFB` | Employee cards, dialog bodies, secondary panels |
| Accent (10%) | `#DC2626` | Kiosk brand shell, NFC focal ring, truly primary branded emphasis |
| Destructive | `#DC2626` | True failure states only |

Accent reserved for:
- kiosk shell branding in the idle header and NFC focal ring
- the default primary branded path when the screen is not communicating semantic success/failure
- thin emphasis on confirmed primary actions, not on every interactive element

Do not use the accent color for queued success states. Queued is a different semantic state, not a brand moment.

### Semantic scan states

| State | Background | Foreground | Usage |
|-------|------------|------------|-------|
| Live confirmed - Masuk | `#DCFCE7` | `#15803D` | Successful on-time or standard entry confirmation |
| Live confirmed - Kembali | `#E0F2FE` | `#0891B2` | Return-from-break confirmation |
| Live confirmed - Istirahat / Istirahat Dulu | `#FEF3C7` | `#92400E` | Break and break-first confirmations |
| Live confirmed - Pulang | `#FEE2E2` | `#B91C1C` | Clock-out confirmation |
| Queued pending | `#FEF3C7` | `#92400E` | Offline-saved state across all action types |
| Offline uncached / retry | `#FEE2E2` | `#B91C1C` | Employee cannot be processed offline |
| Pending follow-up chrome | `#FEF3C7` | `#92400E` | Idle header badge and 36px sync strip continuity |

Queued-state rule:
- The queued screen uses the warm amber pending family as the base visual treatment regardless of action type.
- Preserve the action meaning with a small secondary pill or label inside the screen, not with a full live-success semantic color wash.
- Do not use confetti or a fully final green/red success medallion for queued scans.

## Component Inventory

### 1. Eligible First-Scan Action Stack

Surface:
- `lib/screens/kiosk/kiosk_scan_screen.dart`

Purpose:
- Preserve the one-tap default scan rhythm while exposing a clear break-first alternative only when Phase 55 policy says it is eligible.

Required structure:
1. Existing employee card stays first.
2. Existing section label stays compact.
3. Default primary action stays visually first.
4. `ISTIRAHAT DULU` appears only for eligible first scans and sits directly below the default action with an 8px gap.
5. No extra explainer paragraph above the actions.

Visual contract:
- Both action buttons remain full width and 64px tall.
- Default action keeps stronger visual dominance.
- `ISTIRAHAT DULU` uses the amber break semantic family, not the global red brand accent.
- If the employee is not eligible, the alternative action does not reserve empty space.

### 2. Break-First Confirmation Dialog

Purpose:
- Add one short safety checkpoint so accidental taps do not silently create break-first intent.

Required content:
- icon circle in the amber break family
- title: `Mulai dengan istirahat?`
- one-sentence body
- primary button: `Simpan Istirahat Dulu`
- secondary action: `Batal`

Visual contract:
- 16px radius
- 24px internal padding
- no form fields, checkboxes, or long policy explanations
- primary button may use an amber semantic fill variant for this dialog

Behavior:
- show every time the employee is eligible and taps the alternative action
- never remember or auto-replay a previous answer
- dismiss immediately on confirm or cancel

### 3. Live Confirmed Success State

Purpose:
- Show that the scan was accepted with an authoritative WITA timestamp.

Required content order:
1. semantic success medallion
2. heading `Berhasil!`
3. action status line
4. employee name
5. authoritative time block labeled `Waktu WITA tercatat`
6. break-first helper, only when relevant
7. auto-return footer

Visual contract:
- keep the current centered celebration layout
- keep the existing fast auto-close rhythm of about 3 seconds
- authoritative time is the only display-sized value on the success surface
- confetti stays allowed only for live-confirmed states

Time contract:
- format as `HH:MM WITA`
- never mix this with the ambient device-clock header style

### 4. Queued Pending Success State

Purpose:
- Make offline-saved scans feel successful enough for operations, but unmistakably different from live-confirmed scans.

Required content order:
1. queued-state medallion or cloud-save icon
2. heading `Tersimpan Sementara`
3. body copy that says the device saved the scan and will send it automatically
4. compact action-type badge (`Masuk`, `Istirahat Dulu`, `Selesai Istirahat`, `Pulang`)
5. footer `Lihat tanda pending di layar utama.`

Visual contract:
- use the queued pending amber family as the base treatment
- no confetti
- no `Waktu WITA tercatat` label
- if a local capture time is shown at all, label it as a device-saved time, not an authoritative time
- auto-close timing matches the live state

### 5. Offline Uncached Employee Result State

Surface:
- idle-screen result/error branch before entering scan action selection

Purpose:
- Replace a vague offline failure with a specific retry message when the employee is not cached locally.

Required content:
- title `Belum Bisa Diproses Offline`
- body `Karyawan ini belum tersimpan di perangkat. Sambungkan internet lalu coba lagi.`
- error icon or alert medallion
- auto-reset using the existing short error-reset rhythm

Do not route uncached offline employees into the action-selection screen.

### 6. Pending Indicator Continuity

Surfaces:
- `kiosk_idle_screen` header badge
- 36px slide-down pending strip

Contract:
- both indicators remain in place after Phase 56
- use count-based copy, not technical upload language
- keep the current amber pending family and top-down slide motion
- the queued success screen should explicitly point staff back to these existing indicators instead of adding a new sticky modal

## Interaction Contract

### Scan flow
- If the scan is not a break-first-eligible first scan, the interaction remains a one-tap action.
- If the scan is eligible, `MASUK` remains the visually dominant default path and `ISTIRAHAT DULU` appears as a clear secondary alternative.
- Break-first confirmation is a single yes/no checkpoint only after the alternative action is tapped.
- The scan screen must ask again on every eligible occurrence. No remembered preference, no silent auto-branching.

### Authority feedback
- Live-confirmed scans show the authoritative WITA time returned by the backend.
- Queued scans show a visibly distinct saved-pending state and must not imply final authoritative timing.
- The idle digital clock remains ambient kiosk context only. It is never evidence of the recorded scan time.

### Offline behavior
- Cached employees can continue and receive the queued pending success state if server time is unavailable.
- Uncached employees receive the explicit offline retry state and return to idle.
- Auto-sync remains passive and automatic. Staff should not be forced into a manual sync action during the scan flow.

### Motion and timing
- Keep the existing quick kiosk rhythm:
  - employee-detected toast remains brief
  - success states auto-close in about 3 seconds
  - error states auto-close in about 2.5 seconds
- Queued vs live distinction should come from semantic color, iconography, and copy first; motion can stay minimal.

### Promise boundary
- Live copy may say the scan is recorded.
- Queued copy may say the scan is saved and will be sent automatically.
- Queued copy must not promise that the final review is already settled.

## Layout Contract

### Kiosk idle screen

Visual order remains:
1. existing header with outlet name
2. existing pending badge and pending strip when needed
3. NFC-off banner when needed
4. large ambient device clock
5. NFC focal target
6. bottom status bar

Phase 56 addition:
- do not move the pending chrome elsewhere; queued follow-up stays anchored here

### Kiosk scan screen

Visual order:
1. employee identity card
2. section label
3. context-aware action stack
4. cancel action

Eligible first-scan order:
1. `MASUK`
2. `ISTIRAHAT DULU`

Do not insert a large policy explainer between the employee card and buttons.

### Success states

Visual order:
1. medallion / icon
2. heading
3. status line
4. employee identity
5. time or pending explanation block
6. optional break-first helper
7. auto-return footer

The authoritative time or queued explanation is the informational focal point, not the employee badge row.
