    - `get_attendance_rates`

    - `get_outlet_comparison`
    - `update_employee_streak`
    - `get_overtime_flags`
    - `get_missing_clockouts`
    - `get_arrival_patterns`

    Hardening rules for every redefined function:
    - Preserve `LANGUAGE plpgsql`, `SECURITY DEFINER`, and `SET search_path = public`
    - Keep `REVOKE ALL ON FUNCTION ... FROM PUBLIC`
    - Keep the same `GRANT EXECUTE` target role as the current function contract
    - Use schema-qualified `public.` references where the new body touches project tables/functions
    - Fail closed on auth and claim checks:
      - reject when `auth.role()` is not the expected caller class
      - reject when `app_metadata.app_role` is null, empty, or outside the allowed set
      - reject `kepala_gerai` reads when `managed_outlet_id` is missing or does not match the requested outlet / employee scope

    Implementation guidance by function family:

    1. `get_attendance_rates`, `get_weekly_trend`, `update_employee_streak`, `get_overtime_flags`, `get_missing_clockouts`, `get_arrival_patterns`
       - replace the current `IF v_role NOT IN (...)` guard with an explicit null-safe guard such as:
         - `IF v_role IS NULL OR v_role NOT IN ('admin', 'kepala_gerai') THEN ...`
       - keep the existing kepala-gerai outlet-scope check, but make it fail when `managed_outlet_id` is null

    2. `get_outlet_comparison`
       - replace the current null-sensitive `v_role <> 'admin'` check with `v_role IS DISTINCT FROM 'admin'`

    3. Phase 33 central-dashboard functions
       - audit them while writing the migration
       - do not duplicate or rewrite them unless you find a real regression; they already use the correct null-safe admin-only pattern

    4. Error messages
