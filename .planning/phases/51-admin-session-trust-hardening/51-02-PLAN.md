  <behavior>
    - Valid `app_metadata.app_role = admin` resolves to an unrestricted admin claim.
    - Valid `app_metadata.app_role = kepala_gerai` resolves only when `managed_outlet_id` is present and non-empty.
    - Invalid or missing roles resolve to no privileged claim.
    - `userMetadata` is ignored entirely, even if it contains `app_role` or `managed_outlet_id`.
  </behavior>
  <action>
    1. Create `lib/core/admin_session_claims.dart` with a small shared abstraction for trusted admin session parsing.
       - It may be a value object, a parser helper, or both.
       - Keep it pure and testable.
       - Input should be the current Supabase user or a metadata map.
       - Output should clearly express: admin, kepala gerai with managed outlet, or no privileged claim.

    2. Create `test/phase51/admin_session_claims_test.dart` covering:
       - valid admin claim from `appMetadata`
       - valid `kepala_gerai` claim from `appMetadata` with `managed_outlet_id`
       - `kepala_gerai` with missing or empty `managed_outlet_id` -> invalid
       - unknown role -> invalid
       - `userMetadata` contains `admin` but `appMetadata` is missing or non-privileged -> invalid

    3. Keep the helper independent of widget state so it can be reused from `app.dart`, the login screen, and the settings dialog.
  </action>

       - Expand `test/screens/admin/admin_login_screen_test.dart` so the helper coverage reflects the stricter biometric prerequisites and trusted-session contract.
       - Update `test/providers/app_provider_biometric_test.dart` so disabling biometric still clears any legacy remembered privilege keys.
