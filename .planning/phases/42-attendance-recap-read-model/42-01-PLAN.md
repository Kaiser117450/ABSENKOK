  <action>
    Create `sql/phase_42_portal_attendance_recap_20260323.sql` as an additive, rerunnable migration that defines the recap data contract for the employee portal.

    Required contents:
    1. Add one query-shaped attendance index for the recap read path:
       - index `attendance_logs` by the employee-scoped recap access pattern, for example `(employee_id, scanned_at, type)` or equivalent
       - keep the index name explicit and stable so later phases can reference it

    2. Define one authenticated `SECURITY DEFINER` RPC named `get_portal_attendance_recap(reference_date date default null)` that:
       - resolves the employee internally from the authenticated portal session using `resolve_portal_employee()` or an equivalent internal lookup
       - does not accept `employee_id`, `outlet_id`, or any other caller-controlled identity parameter
       - uses `SET search_path = public`
       - is revoked from `PUBLIC` and granted only to `authenticated`

    3. Use one recap history horizon that supports both month-to-date counts and recent history:
       - compute `effective_date`
       - compute `month_start`
       - compute `history_start` as the earlier of `month_start` and `effective_date - 13 days`
       - return rows from `history_start` through `effective_date`

    4. Merge schedule context and attendance facts into one logical-day row set:
       - scheduled days come from `schedule_entries` and active `schedules`
       - attendance day facts come from `attendance_logs`
       - preserve attendance-only days when logs exist without a matching schedule row
       - preserve scheduled days even when they have no logs

    5. Preserve the shipped overnight rule for ATTN-03:
       - keep recap rows anchored to the logical start day
       - repair orphan next-day `pulang` scans before noon back onto the prior logical day when the prior day already has the relevant work context
       - do not apply a blanket "hour < 12 means previous day" transform to every attendance type

    6. Return a row contract that is sufficient for the later portal helper and surface:
       - `logical_date`
       - `has_schedule`
       - `is_day_off`
       - `outlet_id`, `outlet_name`
       - `shift_name`
       - `start_hour`, `start_minute`, `end_hour`, `end_minute`
       - `ends_next_day`
       - `attendance_status`
       - `first_masuk_at`
       - `first_break_at`
       - `last_kembali_at`
       - `last_pulang_at`
       - `total_break_minutes`
       - `work_minutes`
       - `scan_count`
       - `notes`

    7. Status semantics must be explicit enough for later portal use without another SQL redesign:
       - cover normal/present workdays
       - cover `sakit` and `izin`
       - cover incomplete attendance days (for example `belum_pulang`) without falsely flagging the active current day
       - cover scheduled no-scan days in a way that later phases can surface clearly

    Scope guard:
    - additive migration only
    - no production database application without explicit user confirmation
    - do not rewrite the existing schedule overview RPC unless a tiny compatibility fix is required
  </action>
