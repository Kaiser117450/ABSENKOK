  </read_first>
  <action>
    Create `sql/phase_50_kiosk_boundary_hardening_20260325.sql` as an additive migration. Do not drop tables, columns, or existing data.

    Implement four RPC updates in one file:

    1. `public.activate_kiosk_device(p_outlet_name text, p_password text, p_device_uuid text) returns json`
       - Use the existing `public.verify_kiosk_password(...)` contract instead of re-implementing password verification logic.
       - Resolve a verified outlet from the existing RPC result, then bind `p_device_uuid` to that outlet in `public.kiosk_devices`.
       - If the device UUID is not present yet, insert a new active row with `device_uuid`, `outlet_id`, `created_at`, and `updated_at`.
       - If the device UUID already exists for the same outlet, keep the binding and refresh `updated_at`.
       - If the device UUID is already bound to a different outlet, raise an explicit exception instead of silently rebinding it.
       - Return JSON with the verified `outlet_id`, `outlet_name`, and `device_uuid`.

    2. Replace `public.upsert_kiosk_heartbeat(...)`
       - Keep the same function name and argument list so the existing heartbeat caller stays compatible.
       - Stop inserting a new row from the heartbeat path.
       - Stop changing `outlet_id` on heartbeat updates.
       - Update telemetry only when a matching active `device_uuid` plus `outlet_id` row already exists.
       - Raise a clear exception when the device is not activated for that outlet.

    3. Replace `public.set_device_nickname(...)`
       - Add explicit `auth.jwt() -> 'app_metadata'` role checks.
       - Allow `admin` for any outlet.
       - Allow `kepala_gerai` only when `managed_outlet_id` matches the target kiosk row.
       - Reject all other callers.

    4. Replace `public.archive_device(...)`
       - Apply the same role and outlet-scope checks as `set_device_nickname(...)`.
       - Soft-archive by setting `is_active = false` and `updated_at = now()`.

    Hardening rules for every Phase 50 function:
    - Use `SECURITY DEFINER`
    - Use explicit `SET search_path = public`
    - Schema-qualify project objects as `public.<name>`
    - `REVOKE ALL ON FUNCTION ... FROM PUBLIC`
    - Grant only the minimum role:
      - `activate_kiosk_device` and `upsert_kiosk_heartbeat` -> `anon`
      - `set_device_nickname` and `archive_device` -> `authenticated`
    - Keep the migration safe to re-run with `CREATE OR REPLACE FUNCTION`
  </action>
