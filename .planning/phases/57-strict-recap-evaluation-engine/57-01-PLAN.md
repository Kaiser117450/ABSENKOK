    Required SQL content:
    1. Keep the recap RPC name `public.get_admin_schedule_policy_recap(...)`, but replace its implementation and widen its return table to include the exact new strict fields listed in `<interfaces>`.
    2. Add helper functions with these exact responsibilities:
       - `public.is_strict_recap_manager_exempt(position_text text)` returns true when normalized position text matches `kepala toko` or `kepala gerai`
       - `public.resolve_strict_recap_break_allowance_minutes(employee_contract public.employee_contract, is_overtime boolean)` returns `120` for full-time, `60` for part-time unless `is_overtime = true`, then `120`
       - `public.resolve_strict_recap_primary_status(detail_signals text[], schedule_status text, is_manager_exempt boolean)` chooses the final primary status deterministically
    3. Build strict recap rows from ordered authoritative events:
       - use `attendance_logs.scanned_at`, `initial_scan_intent`, `capture_mode`, and `requires_admin_review`
       - only relevant chain events are `masuk`, `break`, `kembali`, and `pulang`
       - at `NORMAL` outlets, `logical_date` stays the local WITA date
       - at `TWENTY_FOUR_HOUR` outlets, post-midnight chain events stay attached to the prior chain date until a clearly new `masuk` starts a new chain or the prior chain closed with `pulang`
    4. Compute work and break metrics from the chain itself:
       - pair each `break` with the next unmatched `kembali`
       - `total_break_minutes` comes only from paired intervals
       - `net_work_minutes = final_pulang - first_masuk - total_break_minutes`
       - `overtime_minutes = GREATEST(net_work_minutes - required_work_minutes, 0)`
       - `short_work_minutes = GREATEST(required_work_minutes - net_work_minutes, 0)`
       - `excess_break_minutes = GREATEST(total_break_minutes - allowed_break_minutes, 0)`
    5. Encode the locked Phase 57 strict rules exactly:
       - full-time short work turns red when `net_work_minutes < 600`
       - part-time short work turns red when `net_work_minutes < 540`
       - full-time excess break turns red when `total_break_minutes > 120`
       - part-time excess break turns red when `total_break_minutes > 60`, unless the day is overtime, then the allowance becomes `120`
       - late stays red
       - absence stays red
       - manager exemption suppresses red `late`, `short_work`, and `excess_break`, but does not suppress `absence` or `overtime`
       - unscheduled rows still use contract thresholds and also carry `hadir_tanpa_jadwal`
       - a finished `NORMAL` row with unmatched `break` becomes `belum_absen_pulang`, not `excess_break`
       - an active logical day with incomplete chain keeps `active_incomplete` informational only
    6. Preserve the Phase 55/56 fields for compatibility:
       - keep `attendance_status`, `late_kind`, `is_late`, `break_first_eligible`, and `break_first_confirmed`
       - populate them from the strict chain output instead of from pre-Phase-57 date grouping
    7. Populate the new strict fields concretely:
       - `primary_status` uses exact values such as `hadir`, `late`, `short_work`, `excess_break`, `overtime`, `absence`, `belum_absen_pulang`, `exempt_manager`, `hadir_tanpa_jadwal`, `belum_masuk`, `sakit`, `izin`, `cuti`, and `libur`
       - `primary_severity` uses exact values `info`, `yellow`, or `red`
       - `detail_signals` is a `text[]`
       - `detail_notes` is a `text[]`
    8. Comment clearly that the patch is additive-only and still requires explicit user approval before production rollout.
