<objective>
Fix the schedule data flow so Supabase is the source of truth and SQLite is a write-through cache.

Purpose: Schedules currently write to SQLite only (or SQLite-first), making them invisible across devices. This plan reverses the data flow: Supabase-first read, dual-write on save, and normalizes SQLite date storage to prevent cache misses.

Output: `shift_scheduler_screen.dart` with Supabase-first load, dual-write save, auto-generate draft indicator; `schedule_sqlite_service.dart` with normalized date storage.
</objective>
