## Milestone Summary

**Decimal Phases:**

- None

**Key Decisions:**

- Portal attendance recap remains employee-scoped end-to-end through `resolve_portal_employee()` and one recap dataset
- Month-to-date chips and recent-history cards derive from one normalized recap payload, not separate portal queries
- Only `belum_pulang` and `tidak_hadir` are follow-up gaps; current-day in-progress states remain informational
- Historical recap copy is row-aware so past rows no longer use generic "hari ini" wording

**Issues Resolved:**

- Employees can now review recent attendance days without leaving the portal shell
- Portal recap now explains each workday with named timestamps and logical-day-aware status output
- Exception days are visually explicit without escalating current-day in-progress rows into warnings
- Empty, error, and retry states are explicit instead of falling through to generic surfaces
- The v6.3 audit now closes with `7/7` requirements verified and on-disk evidence for phases 42-44
- Production Supabase now contains `get_portal_attendance_recap` and `idx_attendance_logs_employee_recap`

**Issues Deferred:**

- Custom date-range or prior-month recap browsing
- Employee correction/dispute submission from exception days
- Time-off request submission and manager approval workflow
- Reminder or notification flows tied to employee schedules or requests

**Technical Debt Incurred:**

- Repo-wide `npm run check` in `absenkok-website` still reports pre-existing Deno edge-function typing noise outside the recap surface
- `followUpCount` derives from `recap.days` (14-day history horizon) while summary chips stay month-scoped; overlap accepted as minimal for the current use case
- Cross-repo milestones still require manual evidence backfill in this planning repo when the Astro implementation moves faster than archive hygiene
