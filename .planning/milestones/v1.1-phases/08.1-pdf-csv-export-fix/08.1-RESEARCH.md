## 2. Identified Gaps & Issues

### GAP-1: No Summary/Insight Page in PDF (REQ-M3-01 unfulfilled)
**Severity: HIGH**

REQ-M3-01 explicitly requires:
- Page 1 with 2×2 insight cards: Total Hadir, Tingkat Hadir%, Rata-rata Jam Kerja, Tidak Hadir count
- Per-employee aggregate table: Nama | Total Hadir | Avg Masuk | Avg Pulang | Total Kerja | Sakit

Current PDF Rekap Harian is just a flat day-by-day table. No summary statistics, no per-employee aggregation. This is the biggest gap between what was planned (Phase 4 Plan 01) and what exists.

### GAP-2: PDF Format vs UI Mismatch
**Severity: MEDIUM**

- **UI Rekap Harian tiles** show rich visual distinction: status badges (Sakit/Izin/Belum Pulang) with colored backgrounds and emoji
- **PDF Rekap Harian** shows plain text "Sakit"/"Izin"/"Belum Pulang"/"Normal" in a flat column — no visual emphasis
- The PDF format doesn't mirror the visual hierarchy the user sees on screen

### GAP-3: Phase 4 Plan 01 Never Executed — DailySummary Not Extracted
**Severity: LOW (implementation detail)**

Phase 4 Plan 01 wanted to extract `_DailySummary` from private class to `lib/models/daily_summary.dart` for cross-file reuse. This was never done. The model is still private in admin_reports_screen.dart. This blocks building a standalone `PdfReportService` that can compute stats independently.

However, the current approach works around this by mapping `_DailySummary` → `AttendanceDailyPdfRow` (flat DTO) before passing to PdfService. This is acceptable but prevents the PDF service from computing aggregate stats itself.

### GAP-4: Export Refetches Data (Minor UX issue)
**Severity: LOW**

Both `_exportCsv()` and `_exportPdf()` call `_fetchAllRowsForExport()` again, even when the UI already has `_dailyRows` loaded. This means:
- Extra network round-trip on every export
- Potential for different data if DB changed between display and export
- Not a bug, but a UX concern (could use cached data when available)

## 7. Risk Areas
- **PdfService page count:** Adding summary + aggregate pages before day-by-day table increases PDF size
- **Font handling:** Summary page with larger text needs pw.Font.helveticaBold() (already used)
- **Division by zero:** Attendance rate calculation must guard totalEmployees × totalDays = 0
- **Average time computation:** Must use time-of-day minutes (hour×60+minute), NOT epoch timestamps
- **Empty data:** If no rows match filter → insight cards should show 0/"-" not crash
