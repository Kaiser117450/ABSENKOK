# Phase 08.1 Plan 02: PDF Color Coding and Export Cache Summary

**Manual pw.Table with per-status color text replaces plain TableHelper in both Rekap Harian and Per Scan PDFs, plus cached _dailyRows eliminates redundant Supabase fetch on export**

## Accomplishments
- Status column in Rekap Harian PDF now shows colored bold text: Sakit=red (#DC2626), Izin=blue (#2563EB), Belum Pulang=amber (#D97706), Hadir=green (#16A34A)
- Jenis column in Per Scan PDF now shows colored bold text matching UI type badges
- Normal status label changed from 'Normal' to 'Hadir' in both CSV and PDF exports
- Export functions use cached _dailyRows when available, falling back to Supabase fetch only when cache is empty

## Task Commits

1. **Task 1: Change _statusLabel 'Hadir' and use cached data for export** - `38db7f8` (feat)

## Files Created/Modified
- `lib/screens/admin/admin_reports_screen.dart` - Changed 'Normal' to 'Hadir' in _statusLabel; _exportCsv() and _exportPdf() use _dailyRows cache
- `lib/services/pdf_service.dart` - Added _statusTextColor(), _typeTextColor(), _pdfCell() helpers; replaced both pw.TableHelper.fromTextArray calls with manual pw.Table

## Decisions Made
- Manual `pw.Table` chosen over `pw.TableHelper.fromTextArray` because fromTextArray does not support per-cell text color customization — only uniform cell styling is possible via cellStyle
- Cached `_dailyRows` used when non-empty to eliminate redundant Supabase round-trip: the Rekap Harian tab already loads all rows via _loadDailySummaryData(), so re-fetching for export is wasteful
- Fallback fetch preserved for edge case where export button is pressed before the daily tab has loaded (e.g., user exports from Per Scan tab without switching to Rekap Harian first)
