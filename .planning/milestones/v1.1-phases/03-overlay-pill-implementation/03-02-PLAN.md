<interfaces>
Current behavior to replace:
```dart
if (await FlutterOverlayWindow.isActive()) {
  await FlutterOverlayWindow.closeOverlay();
  await Future.delayed(const Duration(milliseconds: 200));
}
await FlutterOverlayWindow.showOverlay(...);
await FlutterOverlayWindow.shareData('$name|$t');
```

Target API surface (service-level):
```dart
enum OverlayShowResult { shown, permissionDenied, showFailed }

static Future<OverlayShowResult> ensureOverlayVisible(OverlayPillState state);
static Future<void> updateOverlayState(OverlayPillState state);
static Future<void> hideOverlayPill();
```

<task type="auto">
  <name>Task 1: Introduce explicit overlay controller API and result enum</name>
  <files>lib/services/kiosk_background_service.dart</files>
  <action>
Add `OverlayShowResult` and refactor overlay methods into a controller-style API:
1. `ensureOverlayVisible(OverlayPillState state)`:
   - Return `permissionDenied` when overlay permission is absent.
   - Call `showOverlay(...)` only when overlay is not active.
   - Always push current state payload after visibility is ensured.
2. `updateOverlayState(OverlayPillState state)`:
   - Push payload via `shareData` when overlay is active.
   - Do not close/reopen overlay.
3. Keep `hideOverlayPill()` as explicit close path only.

Keep old `showOverlayPill` as a backward-compatible wrapper that internally delegates to `ensureOverlayVisible` with idle state.
  </action>
  <verify>
    <automated>flutter analyze lib/services/kiosk_background_service.dart</automated>
  </verify>
  <done>
    - `OverlayShowResult` exists and is used by overlay show path
    - No close/reopen sequence remains in normal overlay update flow
    - `showOverlayPill` wrapper delegates to new controller API
  </done>
</task>

Do not change notification channel behavior in this plan; only overlay control flow and payload format.
