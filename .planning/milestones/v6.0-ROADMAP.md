# Milestone v6.0: Multi-Outlet & Multi-Device Control

**Status:** ✅ SHIPPED 2026-03-22
**Phases:** 31-36
**Total Plans:** 12

## Overview

Provide chain-wide oversight for admins across all outlets and decouple device health tracking so multiple kiosk devices can operate independently without overwriting each other. The milestone started with the implementation phases (31-33), then added closure phases (34-36) to capture rollout evidence, acceptance verification, and final requirement synchronization.

## Milestone Summary

**Decimal Phases:**

- None

**Key Decisions:**

- Persistent kiosk identity uses UUIDv4 stored in `SharedPreferences`
- Device heartbeat state moved from outlet-level fields to `kiosk_devices`
- Central dashboard metrics are served via SECURITY DEFINER RPCs plus role-aware routing
- Gap-closure phases 34-36 were added before ship so rollout evidence and acceptance debt were explicit

**Issues Resolved:**

- Device heartbeats from multiple kiosks on the same outlet no longer overwrite each other
- Admins can manage device nicknames and archiving directly from the dashboard
- Chain-wide device and attendance visibility now exists in a dedicated central admin surface
- Requirement and validation artifacts were synchronized so milestone coverage reached `7/7`

**Issues Deferred:**

- Fresh post-gap-closure audit was not rerun before archival; the archived audit file is the pre-closeout snapshot

**Technical Debt Incurred:**

- Dual PDF service files remain (`pdf_report_service.dart` and `pdf_service.dart`)
