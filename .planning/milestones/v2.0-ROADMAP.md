### Phase 16: Persistent Live Activity Pill

**Goal**: Kiosk tablet shows persistent Dynamic Island-style overlay pill with real-time break status and rotating idle content
**Depends on**: Phase 13 (needs stable employee data model)
**Requirements**: LIVE-01, LIVE-02, LIVE-03, LIVE-04
**Plans**: 2 plans in 2 waves

Plans:
- [x] 16-01: LiveContentProvider service + OverlayPillState displayLabel (Wave 1, TDD)
- [x] 16-02: Overlay rendering + KioskBackgroundService wiring + event priority (Wave 2)

**Details:**

- Accent colors: amber (#F59E0B) when break active, green (#22C55E) when idle
- 26 new unit tests (14 overlay model + 12 live content provider)

## Milestone Summary

**Key Decisions:**
- Archive first, Live Activity last (data model is foundational)
- Only 2 new packages (csv + file_picker) — minimize dependencies
- Kepala Gerai = SQL script only (4 outlets doesn't justify admin UI)
- Overlay data flow via shareData() only (separate isolate)
- Additive migrations only (production DB at 4 outlets)
- Injectable callbacks for LiveContentProvider (testability over Supabase mocking)
- displayLabel defaults to empty string (backward compat)
- ZONA BERBAHAYA pattern for destructive archive action
- Replace content lists completely on each poll (prevent 24h memory growth)

**Issues Resolved:**
- Employee lifecycle management (archive/restore) now fully supported
- Batch employee onboarding eliminated manual one-by-one entry
- Kepala Gerai promotion no longer requires developer intervention
- Overlay pill now shows dynamic content (break status, fun facts, stats)

**Technical Debt:**
- Live Activity pill not yet visually confirmed rotating on physical device (code correct, needs device debugging)
- Phase 15 has no formal PLAN/SUMMARY files (SQL-only phase)
- Traceability table in REQUIREMENTS.md had stale "In Progress"/"Pending" statuses
